# Spec — qrspi-stack

> New capability introduced by the `repo-applicable-artifact-sections` change.
> Project-scoped cheatsheet for this kit (`.claude/skills/qrspi-stack/SKILL.md`)
> with a deterministic `## Repo surface` block, plus the `/qrspi:stack` extension
> to emit that block going forward.

## ADDED Requirements

### Requirement: qrspi-stack cheatsheet ships for this kit
The system MUST create `.claude/skills/qrspi-stack/SKILL.md` as the
project-scoped stack cheatsheet for the QRSPI kit repo. This file MUST describe
the kit's tech stack (markdown command/agent/skill/template files, Node lint at
`scripts/lint.mjs`) and MUST carry the standard `/qrspi:stack` cheatsheet
sections.

#### Scenario: cheatsheet file exists in project scope
- **WHEN** the QRSPI kit repo is inspected
- **THEN** `.claude/skills/qrspi-stack/SKILL.md` is present at project scope
  (`.claude/skills/`, not `claude/skills/`), matching where `qrspi-dogfood` and
  `qrspi-release` already live.

#### Scenario: cheatsheet describes the kit's actual stack
- **WHEN** the cheatsheet body is read
- **THEN** it describes the repo as containing markdown command/agent/skill/template
  files and a Node lint script, with no mention of a database, ORM, SQL,
  HTTP API framework, frontend framework, or auth library.

### Requirement: qrspi-stack cheatsheet carries an explicit Repo surface block
The `qrspi-stack` cheatsheet MUST include a `## Repo surface` block that
explicitly lists all five taxonomy surfaces (`data-store`, `http-api`, `ui`,
`auth`, `typed-nullable`) as absent. This block provides deterministic
surface inference for the kit's own artifacts without relying on prose inference.

#### Scenario: Repo surface block present and lists all surfaces as absent
- **WHEN** `.claude/skills/qrspi-stack/SKILL.md` is read
- **THEN** it contains a `## Repo surface` section listing `data-store: absent`,
  `http-api: absent`, `ui: absent`, `auth: absent`, and `typed-nullable: absent`.

#### Scenario: filter reads the block deterministically
- **WHEN** an agent loads both `repo-surface` and `qrspi-stack` for the kit repo
- **THEN** the `## Repo surface` block is used as-is (no prose inference
  performed) and all five surfaces are treated as absent.

### Requirement: qrspi:stack command extended to emit the Repo surface block
The `/qrspi:stack` command (via `claude/commands/stack.md` and/or its companion
skill) MUST be extended so that newly generated cheatsheets include an explicit
`## Repo surface` block listing each taxonomy surface as present or absent. This
MUST apply to all new cheatsheets generated after this change ships; existing
prose-only cheatsheets are NOT retroactively modified.

#### Scenario: new cheatsheet generated by stack command contains the block
- **WHEN** a user runs `/qrspi:stack` on a repo after this change ships
- **THEN** the generated `<repo>-stack` cheatsheet includes a `## Repo surface`
  section with each of the five taxonomy surfaces assessed as present or absent.

#### Scenario: existing prose-only cheatsheets still work
- **WHEN** a consumer repo has an older cheatsheet with no `## Repo surface`
  block and an agent loads `repo-surface` for that repo
- **THEN** the agent falls back to prose inference (D3-B) and does not fail or
  warn about the absence of the explicit block.
